# Фикс 1 из 2 для FPR 4.084: «рукопожатие»

## Что это

Замена файла `ChatPromptWriter.cs` в проекте Monitor (`MONITOR_2113_PATCH_4084`).
4.084 сломал вставку сообщения в поле ввода чата, перейдя с проверенного
физического клика мышью (как было в FPR_4.015) на попытку сфокусировать поле
через чистый UI Automation (`ValuePattern.SetValue` / `AutomationElement.SetFocus`)
плюс блокирующий `Thread.Sleep(700)` на потоке UI. На реальной странице
ChatGPT/Claude/Gemini это ненадёжно — отсюда «рукопожатие срабатывает через раз
или не срабатывает вовсе».

Этот файл — точный откат к рабочей схеме 4.015: физический `SetCursorPos` +
`mouse_event` в вычисленную «безопасную зону» композера, затем Ctrl+A/Ctrl+V
через `keybd_event`, с проверкой результата через выделение+копирование+сравнение.
Enter не нажимается — отправку по-прежнему делает сам Pilot/Owner.

Вторая проблема («считать ответ» / поиск скрытой кнопки «Копировать» в
`ChatResponseTransfer.cs`) в этом фиксе НЕ трогалась — по договорённости чиним
её отдельной сессией, чтобы не смешивать два независимых изменения в одном шаге.

## Как применить на Windows-машине

1. Откройте ваш рабочий каталог проекта Monitor (тот, где лежит распакованный
   `FPR_4.084_PRODUCT_REALITY_RECOVERY_001`, папка
   `SOURCE/MONITOR_2113_PATCH_4084/MonitorBrowser107/`).
2. Замените файл `ChatPromptWriter.cs` в этой папке на файл из
   `SOURCE/MONITOR_2113_PATCH_4084_FIXED/ChatPromptWriter.cs` (просто скопируйте
   поверх, файл `ChatPromptWriteResult.cs` менять не нужно — сигнатура
   `WriteAsync(WebView2?, string)` не изменилась, остальной код проекта не
   трогается).
3. Пересоберите Monitor как обычно (`RUN_FPR_4.084.cmd` либо ваш обычный build).
4. Проверьте руками: откройте вкладку с ChatGPT/Claude/Gemini в Monitor,
   выполните рукопожатие несколько раз подряд (не только один раз — раньше
   баг проявлялся «через раз»/после нескольких попыток).

## Что важно проверить (Owner Reality Gate, пункт про рукопожатие)

- рукопожатие вставляется с первого нажатия, без повторных попыток;
- Enter по-прежнему не нажимается автоматически — текст просто оказывается в
  поле ввода, отправляете вы сами;
- других файлов и поведения (Considать ответ, GitHub runtime, Graphic Trunk и
  т.д.) это изменение не касается — если что-то из этого сломалось, это не от
  данного фикса.

Если рукопожатие снова не сработает — напишите точное поведение (что видно на
экране, в каком чате, после скольких попыток), это поможет уточнить фикс перед
второй сессией.
